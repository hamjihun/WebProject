# DocVault – 사내 문서중앙화 (가상 드라이브 방식)

직원 PC에 로그인하면 **권한 있는 팀 드라이브만 `내 PC`에 드라이브 문자(O:, W: …)로 나타나고**,
그 드라이브에서 열고 저장하는 모든 파일이 서버에 모여 **버전 관리, 휴지통(180일), 반출 결재, 감사 로그**가 적용됩니다.

```
[직원 PC]                                   [문서중앙화 서버]                      [NAS]
 docvault-agent ─ 로그인/권한 확인 ─────────▶  docvault-server ──── 파일 내용 ────▶ store_dir
 rclone + WinFsp ─ O: 일산영업 (가상 드라이브) ▶  · 권한 검사                            (iSCSI 디스크)
 브라우저 ──────── 웹 화면 (반출/결재/관리) ───▶  · 저장할 때마다 새 버전
                                               · 삭제 → 휴지통 180일 보관
                                               · 반출 신청 → 팀장 결재 → 다운로드
                                               · 모든 작업 감사 로그
                                               · 랜섬웨어 의심 행동 자동 차단
```

직원 PC는 NAS에 직접 접근하지 않습니다. 모든 접근은 서버를 거칩니다.

## 0. 설치 파일은 어디에? (먼저 보세요)

설치할 때는 소스 코드가 아니라 **`DocVault_설치파일`** 폴더(또는 zip)만 쓰면 됩니다.

```
DocVault_설치파일\
 ├ 0_먼저읽어주세요.txt         ← 전체 순서
 ├ 1_서버설치\                  ← 서버 PC에 한 번만 (C:\DocVault 로 복사)
 │   ├ docvault-server.exe
 │   ├ docvault.json             (파일 저장 위치 = NAS 주소)
 │   ├ downloads\docvault-setup.exe  (직원이 웹에서 받아 가는 파일. 그대로 둘 것)
 │   ├ 윈도우서비스로설치.bat
 │   ├ 서비스중지.bat / 서비스시작.bat / 윈도우서비스제거.bat
 │   ├ 방화벽열기.bat
 │   └ 서버설치방법.txt
 ├ 2_직원PC설치\                ← 직원 PC마다
 │   ├ DocVault_PC설치.exe
 │   └ 직원PC설치방법.txt
 └ 3_관리자참고\README.md       ← 이 문서
```

- 만드는 방법: `build.bat`(Windows) 또는 `scripts/build-release.sh` → `dist\DocVault_설치파일`
- 이 저장소의 나머지 폴더(`cmd`, `internal`, `tools` …)는 **프로그램 소스 코드**입니다. 설치할 때는 필요 없습니다.
- 설명서 원본은 `release/` 폴더에 있습니다.

## 1. 주요 기능

| 기능 | 내용 |
|---|---|
| 가상 드라이브 | 로그인한 사용자가 권한을 가진 드라이브만 PC에 연결. 권한을 빼면 1분 안에 자동 해제, 계정 사용중지 시 전부 해제 |
| 권한 | 드라이브별로 그룹/사용자에게 **읽기 / 읽기·쓰기 / 관리(팀장)** 부여. 읽기 권한이면 읽기 전용 드라이브로 연결 |
| 개인문서함 | 모든 사용자에게 F: 개인문서함 (각자 자기 공간만 보임) |
| 버전 관리 | 저장할 때마다 이전 버전 자동 보관. 웹에서 버전 목록 확인·복원. Excel/Word의 "임시파일 → 이름바꾸기" 저장 방식도 하나의 파일 기록으로 이어짐 |
| 휴지통 | 삭제한 파일·폴더는 **180일** 보관 (폴더를 지우면 안의 파일과 함께 하나의 항목으로 보관) 후 자동 영구 삭제 (설정에서 변경). 원래 위치로 복원, 같은 이름이 있으면 "(복원 1)"을 붙여 복원 |
| 반출 결재 | 파일 → [반출 신청] (사유 입력) → 팀장(관리 권한)·관리자가 승인/반려 → 신청자가 **7일 안에 최대 3회** 다운로드 (설정 변경 가능). 신청 시점 버전이 반출됨. 본인 신청은 본인이 결재 불가 |
| 감사 로그 | 로그인, 열람, 새 파일, 수정, 삭제, 이동, 복원, 반출 신청/승인/다운로드, 관리자 작업 등. 기간·사용자·작업·드라이브로 검색, 엑셀(CSV) 저장 |
| 랜섬웨어 대응 | 5분 안에 기존 파일을 200건 이상 수정(덮어쓰기·이름변경, 삭제는 2건을 1건으로 계산)하면 해당 계정의 **쓰기를 자동 차단** (읽기는 가능). 관리자가 확인 후 해제. 피해 파일은 이전 버전이나 휴지통에서 복원 |
| 접속 PC 현황 | 에이전트가 1분마다 보고하는 PC 이름, IP, 연결된 드라이브. 강제 종료 가능 |
| 로그인 보호 | 비밀번호 5회 오류 시 10분 잠금. PC에 저장되는 로그인 정보는 Windows DPAPI로 암호화 |

## 1-1. 유출 차단 (PC 프로그램)

DocVault 드라이브 프로그램은 **파일을 읽으려는 프로그램이 무엇인지 확인해서**, 차단 목록에 있는 프로그램이면 읽기를 거부합니다. 거부되면 PC 오른쪽 아래에 알림이 뜨고 서버 감사 로그에 남습니다.

| 설정 (관리자 → 설정) | 차단 대상 | 기본값 |
|---|---|---|
| PC로 복사 차단 | 명령창(cmd, PowerShell, robocopy, xcopy), 압축 프로그램(반디집, 알집, 7-Zip, WinRAR, WinZip)은 읽기 거부. **탐색기 복사·붙여넣기·드래그는 복사된 파일을 바로 삭제** (아래 설명) | 켜짐 |
| 웹 다운로드 PC 저장 차단 | 크롬·엣지·웨일 다운로드는 개인문서함에 저장. [다른 이름으로 저장]으로 바탕화면 등 PC를 고르면 알림 후 삭제 | 켜짐 |
| 메신저 첨부 차단 | 카카오톡, 텔레그램, 라인, 왓츠앱, 디스코드 | 켜짐 |
| 웹브라우저 업로드 차단 | 크롬, 엣지, 웨일, 파이어폭스 (웹메일 첨부 등). 문서함 PDF를 브라우저로 여는 것도 막힘 | 꺼짐 |
| 추가로 차단할 프로그램 | 직접 입력 (예: `slack.exe, teams.exe`) | 없음 |

- **관리자 계정은 모두 허용**됩니다 (차단 없음). 차단은 일반 사용자 계정에만 적용됩니다.
- **탐색기 복사는 "즉시 삭제 + 팝업" 방식**입니다. 탐색기는 바탕화면·작업 표시줄이기도 해서 읽기를 막으면 오른쪽 클릭, 미리보기만 해도 탐색기 전체가 멈춥니다. 그래서 탐색기는 막지 않고, PC 프로그램이 **로컬 디스크(C:, D: …)와 USB에 새로 생긴 파일**을 확인해서 문서함 파일과 내용이 같으면(SHA-256) 약 1초 안에 삭제하고 **"PC로 복사할 수 없습니다" 팝업 창**을 띄웁니다. (탐색기 자체를 막으면 작업 표시줄까지 멈추므로, 붙자마자 지우는 방식입니다. 파일이 아주 잠깐 보였다 사라질 수 있습니다.) 감사 로그에 "PC 복사 차단 – PC로 복사된 파일 삭제: 위치"로 남습니다.
  - 반출 승인받은 파일은 삭제하지 않습니다.
  - Windows·Program Files·ProgramData·AppData(프로그램 임시파일) 폴더는 확인하지 않습니다.
- **웹 다운로드**: PC 설치 프로그램이 크롬·엣지·웨일의 **기본** 다운로드 위치를 **개인문서함(F:)** 으로 정합니다 (Windows 권장 정책: 브라우저 설정에서 바꿀 수 있음. 그래서 브라우저에 "조직에서 관리하는 브라우저입니다"가 보입니다). 관리자는 바탕화면 등으로 바꿔 써도 되고, 일반 사용자가 PC 폴더로 바꾸면 받은 파일이 삭제되고 알림이 뜹니다. 그룹웨어 첨부 등을 받으면 개인문서함에 저장되고, 받은 파일을 바로 여는 것도 됩니다.
  - [다른 이름으로 저장]에서 바탕화면·D: 등 PC를 고르면 다운로드가 시작되는 순간 **"PC에 저장할 수 없습니다. DocVault 문서함에 저장하세요"** 알림이 뜨고, 다운로드가 끝나면 그 파일을 삭제합니다 (감사 로그: "PC 저장 차단").
  - 삭제는 일반 사용자에게만 합니다. DocVault를 제거하면 브라우저 설정은 원래대로 돌아갑니다.
  - 파이어폭스는 다운로드 위치 고정이 안 됩니다 (PC 저장 시 삭제는 적용).
- **반출 신청 → 반출 폴더**: 탐색기에서 문서함 파일을 오른쪽 클릭 → **[DocVault 반출 신청]** (Windows 11은 [더 많은 옵션 표시] 안) → 사유 입력. 웹 화면의 [반출 신청]도 같습니다.
  - 결재자가 승인하면 그 파일(신청 당시 버전)이 신청자의 **개인문서함\반출** 폴더에 들어갑니다. 같은 이름이 있으면 `견적 (2).xlsx`처럼 들어갑니다.
  - **반출 폴더에 있는 그 파일만** 바탕화면·USB 등 PC로 꺼낼 수 있습니다. 내용이 같아도 **원본(다른 폴더의 파일)은 꺼낼 수 없습니다.** (드라이브가 "반출 폴더에서 방금 꺼낸 파일"인지 확인해서, 한 번 반출했다고 원본이 계속 빠져나가지 않게 합니다.)
  - 반출 폴더에는 직원이 파일을 넣거나, 고치거나, 이름을 바꿀 수 없습니다 (승인된 파일만 있도록). **반출 폴더 자체는 삭제·이름변경이 안 됩니다** (항상 있어야 반출을 받습니다). 폴더 안의 파일은 열어 보기·삭제가 됩니다.
  - **후결재**: 신청할 때 [후결재]를 체크하면 바로 반출 폴더에 들어가고 결재는 나중에 받습니다 ("후결재 대기"). 결재자가 반려하면 반출 폴더에서 회수됩니다 (이미 밖으로 복사한 것은 감사 로그에 남음). [관리자 → 설정 → 후결재 반출 허용]으로 끌 수 있습니다.
- **사용자별 예외**: [관리자 → 사용자 → 수정 → PC로 복사 허용]을 체크하면 그 사람은 "PC로 복사 차단"에서 제외됩니다.
- **막히지 않는 것**: Excel·한글 등 업무 프로그램은 정상적으로 열고 저장합니다. 문서함 안에서의 이름변경, 삭제, 같은 드라이브 안의 잘라내기/붙여넣기(이동)도 됩니다.
- **한계**
  - Excel·Word에서 [다른 이름으로 저장]으로 바탕화면에 저장하는 것은 막지 못합니다. 감사 로그의 열람 기록으로 추적합니다.
  - 화면 캡처나 휴대폰 촬영은 막지 못합니다.
  - 다른 사람이 문서함에 올린 파일과 **내용이 완전히 같은 파일**을 메일 등으로 받아 PC에 저장해도 삭제됩니다 (문서함에 이미 있는 파일이므로 문서함에서 여세요).
  - 차단 목록에 없는 프로그램은 막히지 않습니다. 필요하면 "추가로 차단할 프로그램"에 넣으세요.
  - 명령창·압축 프로그램 복사가 거부될 때 복사 대상 위치에 빈 파일이 남을 수 있습니다.
- 드라이브 프로그램은 rclone(MIT 라이선스)을 DocVault용으로 줄이고 이 차단 기능을 더한 것입니다 (`tools/dvmount`).

## 1-0. PC 프로그램 로그인 (0.8.3부터)

- PC 프로그램을 켤 때마다(Windows 시작 포함) 로그인 창이 뜨고, **[접속하기]**를 눌러야 드라이브가 연결됩니다.
- **[아이디·비밀번호 저장]**을 체크하면 다음부터 둘 다 채워져 있어 [접속하기]만 누르면 됩니다 (이 Windows 사용자만 풀 수 있게 암호화해 PC에 저장).
- 자동 업데이트로 다시 시작할 때는 로그인 없이 그대로 이어집니다.
- 작업 표시줄 아이콘 → **[업데이트 확인]**: 서버에 새 버전이 있으면 바로 받아 설치하고 적용할지 묻습니다.
- **사내 망이 아니면 로그인되지 않습니다.** [접속하기]를 누르면 먼저 서버와 통신을 확인하고, 안 되면 "사내 망(DocVault 서버)에 연결되어 있지 않습니다"라고 알립니다 (재택·외부에서는 사내망/VPN 연결 후 사용).
- 로그인 창에 **서버 주소** 칸이 항상 보입니다. 서버 IP가 바뀌면 여기서 고쳐 [접속하기]를 누르면 저장됩니다 (예: `192.168.50.10:8080`).

## 1-1-1. 서버가 멈췄을 때 (0.8.0부터)

- PC 프로그램이 3초마다 서버를 확인합니다. 서버가 **약 6초 동안 응답하지 않으면 문서 드라이브 연결을 잠시 해제**하고 알림을 띄웁니다. 드라이브가 응답 없는 서버를 기다리느라 탐색기·작업 표시줄이 멈추는 것을 막기 위해서입니다.
- 서버가 돌아오면 **몇 초 안에 자동으로 다시 연결**하고 알립니다. 서버 업데이트(서비스 중지 → 교체 → 시작) 때도 같습니다.
- 서버가 멈추기 직전에 저장해 아직 올라가지 않은 파일은 PC에 남아 있다가, 다시 연결되면 자동으로 올라갑니다.
- 드라이브 프로그램 자체가 응답하지 않으면(30초) 그 드라이브를 다시 연결하고 알립니다.

## 1-2. PC 프로그램 자동 업데이트 (0.7.0부터)

- 서버의 `downloads\docvault-setup.exe`만 새 버전으로 바꾸면, **각 PC가 10분 안에 스스로 받아 설치**합니다. 직원이 할 일은 없습니다.
- PC 설치 때 **"DocVault 자동 업데이트" Windows 서비스**가 함께 등록됩니다 (시스템 권한으로 실행 → 직원 계정에 관리자 권한이 없어도 됨).
- PC를 켜면 **20초 뒤** 바로 확인하고, 그 뒤로는 10분마다 확인합니다. 새 버전은 **Excel·Word·한글 등 문서 프로그램이 열려 있지 않으면 바로** 적용됩니다 (드라이브가 몇 초 끊겼다 다시 연결). 문서 프로그램이 열려 있으면 닫는 즉시 적용되고, 트레이 아이콘 → **[업데이트 적용]**으로 바로 적용할 수도 있습니다.
- 진행 확인: 웹 → 관리자 → **접속 현황**에 PC별 버전과 "업데이트 대기"가 보입니다. PC의 기록은 `C:\ProgramData\DocVault\update.log`.
- **0.6.0 이하 PC는 한 번만 직접 다시 설치**해야 합니다 (자동 업데이트 서비스가 0.7.0부터 들어 있음).
- 보안 참고: PC는 서버에서 받은 설치 파일을 시스템 권한으로 실행합니다. 사내망 밖에 서버를 열지 말고, 가능하면 HTTPS(`tls_cert`)를 쓰세요.

## 2. 구성 파일

| 파일 | 설치 위치 | 설명 |
|---|---|---|
| `docvault-server.exe` | 서버 (테스트: Windows 10 PC / 운영: Windows Server 2019) | 서버 프로그램 (웹 화면 포함) |
| `downloads\docvault-setup.exe` | 서버 폴더 안 (`docvault-server.exe` 옆의 `downloads` 폴더) | **직원 PC 통합 설치 파일**. 직원이 웹 로그인 화면의 [PC 프로그램 설치]로 내려받음 |

통합 설치 파일 안에는 다음이 모두 들어 있어서, 직원 PC에 따로 받을 것이 없습니다.
- **WinFsp**: Windows에 가상 드라이브를 만들 수 있게 해 주는 구성요소 (무료, 자동 설치)
- **rclone**: 서버에 접속해 드라이브(O:, W: …)를 연결하는 도구 (무료)
- **DocVault 에이전트**: 로그인하고 권한 있는 드라이브만 연결
- **서버 주소**: 서버 웹에서 내려받을 때 자동으로 들어감

### 빌드 (exe 만들기)

1. https://go.dev/dl/ 에서 Go (Windows MSI)를 설치합니다.
2. 이 폴더(`docvault`)에서 `build.bat`을 더블클릭합니다. WinFsp와 rclone은 자동으로 내려받습니다.
3. `dist\server` 폴더가 생깁니다. 이 폴더를 통째로 서버에 복사하면 됩니다.
   ```
   dist\server\docvault-server.exe
   dist\server\downloads\docvault-setup.exe
   ```

## 3. Windows 10 PC에서 테스트 서버 만들기

### 3-1. 서버 실행

1. `C:\DocVault` 폴더에 `docvault-server.exe`와 `downloads` 폴더(`docvault-setup.exe` 포함)를 넣습니다.
2. `docvault-server.exe`를 더블클릭합니다. 처음 실행하면 다음이 자동으로 생깁니다.
   - `docvault.json` (설정 파일)
   - `data\` (DB, 감사 로그)
   - `store\` (파일 내용)
   - `data\초기관리자비밀번호.txt` (**admin 계정 비밀번호**)
3. 브라우저에서 `http://localhost:8080` 에 접속한 뒤 `admin`과 위 비밀번호로 로그인합니다.
4. 다른 PC에서도 접속하려면 방화벽 포트를 엽니다 (관리자 권한 명령 프롬프트):
   ```
   netsh advfirewall firewall add rule name="DocVault" dir=in action=allow protocol=TCP localport=8080
   ```
   다른 PC에서는 `http://<서버PC IP>:8080` 으로 접속합니다.

### 3-2. 설정 파일 (`docvault.json`)

```json
{
  "listen": ":8080",
  "data_dir": "C:\DocVault\data",
  "store_dir": "\\192.168.50.201\DocVaultStore",
  "tls_cert": "",
  "tls_key": "",
  "trust_proxy": false,
  "public_url": "",
  "store_user": "NAS 아이디",
  "store_password": "NAS 비밀번호"
}
```
- `store_user` / `store_password`: `store_dir`이 NAS 공유폴더일 때, 서버가 그 계정으로 NAS에 로그인합니다. **Windows 서비스로 실행하면 필수**입니다 (서비스는 시스템 계정으로 실행되어 탐색기에 저장한 비밀번호를 쓰지 못함).
- 경로는 **탐색기 주소창에 쓰는 것과 똑같이** 적습니다 (역슬래시를 두 번씩 쓸 필요 없음. 예전 방식으로 두 번씩 써도 동작합니다).
- `store_dir`: 파일 내용이 저장되는 곳입니다. 운영 서버에서는 **NAS iSCSI로 연결한 디스크**(예: `E:\DocVaultStore`)로 지정합니다.
- `public_url`: 직원 PC가 서버에 접속하는 주소입니다 (예: `http://192.168.50.10:8080`). 비워 두면 직원이 웹에 접속한 주소를 그대로 씁니다. 설치 파일에 들어가는 서버 주소가 이것입니다.
- 설정을 바꾼 뒤에는 서버를 다시 시작합니다.

### 3-3. 기본 설정 (웹 관리자 화면)

1. **그룹(팀)**: `일산영업팀`, `일산전자개발팀` 등을 추가합니다.
2. **사용자**: 직원 계정을 추가하고 그룹을 체크합니다.
3. **드라이브·권한**: `일산영업` (문자 O), `일산전자개발팀` (문자 W) 등을 추가한 뒤 [권한]에서 다음을 지정합니다.
   - `일산영업팀` 그룹 → 읽기/쓰기
   - 팀장 계정 → 관리(팀장·결재)
4. **설정**에서 휴지통 보관 기간(기본 180일), 반출 기간, 랜섬웨어 기준 등을 확인합니다.

### 3-4. 직원 PC 설치 (직원이 직접, 1분)

1. 직원 PC의 브라우저로 `http://<서버 IP>:8080` 에 접속합니다.
2. 로그인 화면 아래 **[💻 PC 프로그램 설치]** 를 눌러 `docvault-setup.exe`를 받고 실행합니다.
   - "이 앱이 디바이스를 변경하도록 허용하시겠어요?" 창이 뜨면 [예]를 누릅니다. **PC 관리자 권한이 필요합니다.** 직원 계정에 관리자 권한이 없으면 IT 담당자가 대신 실행합니다.
   - Windows에서 "PC 보호" 창이 뜨면 [추가 정보] → [실행]을 누릅니다. 인증서 서명이 없는 사내 프로그램이라서 나오는 경고입니다.
3. 설치가 끝나면 **DocVault 로그인 창**이 뜹니다. 아이디와 비밀번호를 입력합니다.
4. 잠시 후 `내 PC`의 **장치 및 드라이브**에 권한 있는 드라이브가 DocVault 아이콘으로 나타납니다. 예: `일산영업 (O:)`
   - 삭제할 때는 "영구적으로 삭제할까요?" 창이 뜨지만, 지운 파일은 **서버 휴지통에 180일** 보관됩니다.
5. 이후에는 Windows를 켤 때마다 자동으로 연결됩니다.

**작업 표시줄 오른쪽 아래 DocVault 아이콘** (클릭하면 메뉴가 열립니다)

| 메뉴 | 기능 |
|---|---|
| (맨 위) 사용자 이름, 연결된 드라이브 목록 | 현재 상태 확인 |
| 내 PC 열기 | 탐색기 열기 |
| 웹 문서함 열기 | 버전 기록, 휴지통, 반출 신청 |
| 지금 다시 연결 | 권한 변경을 바로 반영하거나 끊긴 드라이브 다시 연결 |
| 버전 정보 | 프로그램 버전, 서버 주소, 로그 폴더 |
| 로그 폴더 열기 | 문제가 생겼을 때 확인 |
| 로그아웃 | 드라이브 연결을 해제하고 로그인 창으로 돌아감 (다른 직원이 같은 PC를 쓸 때) |
| 종료 | 드라이브 연결을 해제하고 프로그램 종료 (Windows를 다시 켜면 자동 실행) |

| 할 일 | 방법 |
|---|---|
| 제거 | Windows [설정 → 앱 및 기능 → DocVault 문서 드라이브 → 제거]. 드라이브 연결 해제, 서버 로그아웃, 프로그램·rclone·자동 실행·사용자 데이터(로그인 정보, 캐시, 로그) 삭제, **함께 설치했던 WinFsp도 제거**합니다 (DocVault 설치 전부터 있던 WinFsp는 다른 프로그램을 위해 남김) |
| 프로그램을 종료했다가 다시 켜기 | 시작 메뉴 → **DocVault 문서 드라이브** |
| 업데이트 | 새 `docvault-setup.exe`를 서버 `downloads` 폴더에 넣고, 직원 PC에서 다시 설치 |
| 로그 위치 | `%LOCALAPPDATA%\DocVault\logs\` |

## 4. 운영 서버 (Windows Server 2019) 설치

1. **VM 준비**: vCPU 4~8, RAM 16GB, OS 디스크 100GB, Windows Server 2019. **도메인에는 가입하지 않습니다.**
2. **NAS 연결**: NAS에서 iSCSI LUN을 만들고 서버의 iSCSI 초기자로 연결 → 디스크 관리에서 포맷 (예: `E:`).
3. `C:\DocVault`에 `docvault-server.exe`를 넣고 한 번 실행해 `docvault.json`을 만든 뒤 `store_dir`을 `E:\DocVaultStore`로 바꿉니다.
4. 관리자 권한 명령 프롬프트에서 다음을 실행합니다.
   ```
   C:\DocVault\docvault-server.exe install
   ```
   Windows 서비스 "DocVault 문서중앙화 서버"로 등록되어 **부팅 시 자동 시작**되고, 오류가 나면 자동으로 다시 시작합니다.
   - 서비스 중지/시작: `docvault-server.exe stop` / `start`
   - 서비스 제거: `docvault-server.exe uninstall` (데이터는 남음)
   - 서비스 로그: `C:\DocVault\logs\`
5. **HTTPS (운영 필수)**: 인증서 파일(PEM)을 `tls_cert`, `tls_key`에 지정하고 `listen`을 `":443"`으로 바꿉니다. 직원 PC의 `agent.json`도 `https://` 주소로 바꿉니다.
6. **방화벽**: 443(또는 8080) 포트만 엽니다. 원격 데스크톱은 관리자 PC IP에서만 허용합니다.
7. **백업**:
   - `C:\DocVault\data` (DB)와 `store_dir`(파일 내용)을 **같은 시점에** 백업해야 합니다.
   - NAS 스냅샷(변경 불가 옵션)과 백업 NAS 복제를 설정합니다.
   - VM 스냅샷은 업데이트 전에 찍습니다.
8. **비밀번호 분실 시**: `docvault-server.exe reset-password admin 새비밀번호`

> 테스트 PC에서 쓰던 `data`, `store` 폴더를 그대로 옮기면 테스트 데이터도 이어서 쓸 수 있습니다.

## 5. 동작 방식 메모

- **버전 저장**: 같은 파일을 다시 저장하면 새 버전이 됩니다. 내용이 같으면 버전을 만들지 않습니다. 같은 내용의 파일은 저장소에 한 번만 저장됩니다.
- **Office 임시 파일**: `~$파일.xlsx`, `6C3F2A10`, `*.tmp` 같은 임시·잠금 파일은 버전, 휴지통, 로그에서 제외됩니다.
- **용량 제한**: 드라이브마다 GB 단위로 설정합니다. 넘으면 저장이 거부됩니다. 현재 버전만 계산하고 이전 버전과 휴지통은 제외합니다.
- **자동 정리** (6시간마다, [설정 → 지금 정리 실행]으로 즉시 실행 가능):
  - 보관 기간이 지난 휴지통 항목 영구 삭제
  - 180일이 지난 이전 버전 정리 (단, 파일마다 최근 20개는 유지)
  - 기한이 지난 반출 승인 만료
  - 쓰이지 않는 파일 내용 삭제
- **반출 중인 버전**은 결재 대기 또는 승인 상태인 동안 정리되지 않습니다.

## 5-0. 드라이브 캐시

- 드라이브는 `--vfs-cache-mode full`로 연결합니다. 읽은 부분도 PC의 `%LOCALAPPDATA%\DocVault\cache`에 잠시(최대 1시간, 20GB) 보관해서, 탐색기 메뉴·아이콘·exe 서명 확인·백신처럼 파일을 여러 번 건너뛰며 읽는 경우에도 서버에서 다시 받지 않습니다 (150MB exe 기준 27초 → 1초).
- 캐시는 프로그램이 시작할 때와 1시간 뒤 지워집니다. 차단 프로그램은 캐시에 있는 파일도 읽지 못합니다.

## 5-1. 데이터는 어디에 저장되나

| 무엇 | 위치 | 비고 |
|---|---|---|
| 파일 내용 | `store_dir` (기본: 서버 프로그램 폴더의 `store\`) | 파일 이름이 아니라 내용의 고유값(해시)으로 저장됩니다 (`store\blobs\ab\cd\abcd…`). 같은 내용은 한 번만 저장됩니다 |
| 파일 이름, 폴더 구조, 버전, 휴지통, 권한, 로그 | `data_dir\docvault.db` | 이 DB가 있어야 `store`의 내용을 파일로 되살릴 수 있습니다 |

- `store` 폴더를 탐색기로 열면 이름 없는 파일만 보입니다. 정상입니다. **문서는 반드시 드라이브(F:, O: …)나 웹 화면을 통해서만** 다룹니다.
- 서버 PC가 직접 접근할 수 있으니, 운영 서버에서는 이 폴더를 NAS(iSCSI)로 옮기고 일반 사용자 접근을 막습니다.
- **저장 위치를 옮기려면**: 서버를 종료하고 → `store` 폴더를 통째로 새 위치(예: `E:\DocVaultStore`)로 복사 → `docvault.json`의 `store_dir`을 바꾼 뒤 → 서버를 다시 시작합니다.
- **드라이브 용량 표시**: 드라이브에 용량 제한(GB)을 설정하면 그 값이 표시됩니다. 0(제한 없음)이면 `store_dir`이 있는 디스크의 실제 남은 용량이 표시됩니다. 개인문서함의 용량 제한은 **1인당** 적용됩니다.
