1장애 등급과 안내 채널

장애는 영향 범위에 따라 4개 등급으로 나눕니다. 등급은 IT 담당이 판단해 공지하며, 등급에 따라 누가 어떤 채널로 안내하는지가 정해집니다. 직원은 공지에 적힌 등급을 보고 이 매뉴얼의 해당 장을 펼치면 됩니다.

등급상황예시안내 주체 · 채널직원이 볼 장
1등급 · 전사 중단서버실 전체 또는 네트워크 전체가 멈춰 모든 시스템을 쓸 수 없음정전·UPS 소진, 화재, 수해, 코어 스위치·방화벽 고장, 랜섬웨어 확산경영진 결정 → IT 담당 + 경영지원팀이 단체 채팅방·전화 콜트리·사내 방송으로 전파4장, 7장
2등급 · 핵심 시스템 중단ERP·그룹웨어·AD(로그인)·인터넷 회선 중 하나가 멈춰 전사 업무에 영향ERP 서버 다운, 그룹웨어 메일 불가, 로그인 불가, 인터넷 단절IT 담당이 단체 채팅방 + 부서장 문자로 즉시 공지, 30분마다 진행 상황 갱신3장
3등급 · 일부 시스템 중단특정 서버나 특정 부서·층만 영향문서중앙화 접속 불가, MES 실적 입력 불가, 3층 네트워크 불통, 프린터 불가IT 담당이 그룹웨어 공지(가능 시) + 해당 부서장에게 안내3장, 5장
4등급 · 개인 장애한 사람의 PC·계정만 문제내 PC 부팅 불가, 내 계정 잠김, 내 자리 랜선 불량본인이 IT 접수(전화·단체방·그룹웨어 IT요청), 공지 없음5-5절

안내 채널 우선순위

그룹웨어가 살아 있으면 그룹웨어 공지가 1순위입니다. 그러나 그룹웨어 자체가 멈추는 경우가 많으므로 그룹웨어와 무관한 채널을 반드시 두 개 이상 운영합니다.

순위채널쓰는 경우비고
1그룹웨어 전사 공지 · 팝업그룹웨어 정상, 다른 서버 장애가장 기록이 잘 남음
2사내 비상 단체 채팅방 (카카오톡·네이버웍스 등, 스마트폰)그룹웨어·네트워크 장애, 정전회사 회선과 무관한 이동통신망이라 정전 시에도 동작. 전 직원 사전 가입 필수
3부서장 전화·문자 콜트리단체방 미가입자, 현장 근무자7장 연락망 사용. 부서장은 팀원 수신 확인까지 책임
4사내 방송 · 게시판 · 현장 구두 전파공장 생산 현장, 전사 동시 안내방송 설비가 정전 시 동작하는지 사전 확인

2장애 발생 시 공통 행동 요령

어떤 시스템이 멈추든 직원의 첫 행동은 같습니다. 아래 흐름도대로 범위를 확인하고, 보고하고, 공지를 기다린 뒤, 대체 수단으로 전환합니다. 이 순서를 지키면 IT 담당에게 같은 문의가 수십 건 몰리는 것을 막고 복구가 빨라집니다.

보고할 때 말할 것 (한 줄이면 충분)

「어떤 시스템이 · 몇 시부터 · 어떤 화면(메시지)으로 · 누구까지 안 되는지」를 부서장 또는 IT 담당에게 전합니다. 예: “ERP 로그인 화면에서 ‘서버에 연결할 수 없습니다’ 나옴, 9시 40분부터, 영업팀 전원.” 화면을 스마트폰으로 찍어 단체방에 올리면 원인 파악이 훨씬 빨라집니다.

해야 할 것

  • 작업 중이던 문서·엑셀은 내 PC에 즉시 저장(다른 이름으로 저장 → 바탕화면 「장애임시」 폴더)
  • 부서장 보고 후 공지 대기, 공지에 적힌 대체 수단으로 전환
  • 장애 중 처리한 업무는 수기 대장·엑셀에 기록(복구 후 입력용)
  • 정전 시 노트북은 배터리로 저장 후 덮개 닫기, 데스크톱은 그대로 두기
  • 보안사고 의심 시 랜선 분리 후 즉시 신고

하지 말아야 할 것

  • 서버실·네트워크 장비함 출입, 장비 전원·케이블 조작
  • PC 반복 재부팅, 로그인 반복 시도(계정 잠김 유발), 비밀번호 변경
  • 도면(Gerber·CAM)·원가·고객 정보를 개인 USB·개인 클라우드·개인 메일로 반출
  • IT 담당에게 개별 전화 반복(부서장 통해 취합), 확인되지 않은 소문 전파
  • 임의 소프트웨어 설치, 방화벽·백신 끄기

3서버별 장애 대응 매뉴얼

사내 서버 11대를 기준으로 작성했습니다. 서버 코드(SRV-01 등)는 IT 공지에 그대로 사용하며, 실제 구성과 다른 항목은 IT 담당이 수정합니다. 각 서버가 멈췄을 때 직원이 겪는 증상 → 대체 수단 → 복구 후 할 일 순서로 정리했습니다.

서버 구성 가정 (실제 구성에 맞게 조정)

그룹웨어, ERP(앱), ERP DB, 문서중앙화(ECM), MES(생산관리), 파일서버(CAM·부서 공유), AD 도메인 컨트롤러(DNS·DHCP 겸용), Veeam 백업, 보안 관리(백신·DLP·NAC), 홈페이지(DMZ), 출입·근태 서버. 이 외 방화벽·코어 스위치·인터넷 회선·전화(IP-PBX)는 5장에서 다룹니다.

3-2. 서버별 상세 카드

SRV-01

그룹웨어 서버

2등급RTO 4h · RPO 24h
증상
그룹웨어 로그인 화면이 안 뜨거나 “서버 응답 없음”, 메일 송수신 멈춤, 결재 상신·승인 불가, 일정·회의실 예약 불가, 아웃룩 연동 시 동기화 오류.
직원 대응
  • 메일: 회사가 사전에 승인한 개인(임시) 메일 계정을 사용합니다. 규칙 ① 제목 앞에 [임시발송] 표기 ② 서명에 회사명·부서·전화번호 기재 ③ 견적서·도면 첨부는 반드시 암호 ZIP 후 암호는 전화·문자로 별도 전달 ④ 거래처에는 “그룹웨어 장애로 임시 계정에서 보냅니다. 회신은 이 주소로 주세요” 한 줄 안내 ⑤ 발송 메일은 회사메일주소를 숨은참조(BCC)에 넣어 복구 후 사내 메일함에 남게 합니다.
  • 긴급 수신 확인: 발주·납기 회신처럼 급한 건은 거래처에 전화로 “메일 보냈는지” 확인합니다. 도착하지 않은 메일은 복구 후 대부분 순차 수신되지만, 4시간 이상 장애 시 재발송을 요청합니다.
  • 전자결재: 총무팀이 보관하는 「긴급 수기 결재 용지」에 작성해 결재권자 서명을 받습니다. 결재권자가 외부에 있으면 문자·카카오톡으로 내용을 보내 “승인” 답을 받고 화면을 캡처해 보관합니다. 복구 후 소급 상신하며 제목에 [소급/장애 09-15]를 붙입니다.
  • 일정·회의실: 부서 화이트보드와 단체방으로 조율합니다. 회의실은 총무팀이 종이 예약표로 임시 운영합니다.
  • 공지·게시판: 전사 공지는 사내 비상 단체방, 부서 공지는 부서 단체방을 씁니다.
  • 주소록: 스마트폰 연락처와 명함 관리 앱, 거래처 대표번호를 사용합니다.
IT 조치
서비스·DB·디스크 용량 확인 → 서비스 재시작 → 실패 시 Veeam 스냅샷 복원(전일 시점) → 메일 릴레이·MX 큐 확인(외부 메일이 스팸 게이트웨이/통신사 큐에 대기 중인지) → 복구 공지.
복구 후 할 일
임시 계정으로 주고받은 메일 중 업무 기록이 필요한 것은 사내 메일로 전달(Forward), 수기 결재는 24시간 내 소급 상신, 임시 계정에 남은 회사 자료는 삭제.
SRV-02 · SRV-03

ERP 서버 · ERP DB 서버

2등급RTO 4h · RPO 1h(DB 로그)
증상
ERP 클라이언트 로그인 불가, “DB 연결 오류”, 조회는 되나 저장 시 멈춤(DB 장애), 작업지시서·거래명세서 출력 불가, MES 실적이 ERP에 반영되지 않음.
직원 대응

모든 부서 공통 원칙은 “종이·엑셀에 먼저 적고, 복구 후 순서대로 입력”입니다. 부서별 수기 양식은 총무팀 서랍과 문서중앙화 「비상양식」 폴더(오프라인 사본은 각 부서 PC)에 둡니다.

  • 영업·수주: 엑셀 견적 템플릿으로 견적 발행(견적번호는 임시-YYMMDD-부서-일련). 수주는 「수기 수주장」에 고객·품번·수량·납기 기록. 고객 PO(발주서) 원본은 반드시 보관.
  • 생산관리: 장애 직전에 출력된 작업지시서·생산계획을 기준으로 생산 진행. 신규 지시는 생산관리팀장이 수기 작업지시서를 발행하고 번호를 채번. 긴급 오더는 영업→생산관리 전화 확인 후 수기 지시.
  • 자재·구매: 「수기 입출고 대장」(품목·LOT·수량·출고처·서명) 기록. 원자재(동박적층판, 드라이필름, 잉크, 약품) 불출은 반드시 대장 기재 후 이동. 발주는 엑셀 발주서로 협력사에 메일·팩스 발송.
  • 출하·물류: 엑셀 「수기 거래명세서」 양식으로 출하(2부 출력, 1부 고객 서명 회수). 출하 LOT·수량을 반드시 기록해 복구 후 ERP 출하 처리. 수출 건은 인보이스·패킹리스트 엑셀 양식 사용.
  • 품질: 검사 성적서는 엑셀 양식으로 발행, 부적합은 수기 부적합 보고서로 기록.
  • 회계·경리: 세금계산서는 국세청 홈택스에서 직접 발행, 입출금은 인터넷뱅킹으로 처리하고 「수기 전표」에 기록. 급여·마감 기한이 겹치면 회계팀장이 경영진과 일정 조정.
IT 조치
앱 서버·DB 서버 어느 쪽인지 분리 확인 → 서비스 재기동 → DB 무결성 점검 → 필요 시 최근 DB 백업 + 트랜잭션 로그로 복원 → ERP 벤더 긴급 지원 요청(계약 연락처 9장) → 복구 후 마지막 정상 저장 시각을 공지(그 이후 입력분은 재입력 대상).
복구 후 할 일
IT가 공지한 “마지막 정상 저장 시각” 이후 건을 부서별 담당자가 수주 → 작업지시 → 입출고 → 출하 → 회계 순서로 입력(순서가 바뀌면 재고·매출이 틀어짐). 임시 번호는 정식 번호로 대체하고 대응표를 남깁니다. 자재팀은 복구 후 3일 내 주요 자재 실사.

  • 급한 출력은 프린터에 USB 직결하거나 부서 내 공유 프린터 담당 PC에서 출력합니다.

복구 후 할 일
공지에 따라 PC 재부팅 및 재로그인, 로그인 안 되는 사용자는 IT 접수. IP 접속으로 바꿔 둔 즐겨찾기는 원래 주소로 복원.

4전체 셧다운 대응 (정전 · 화재 · 수해 · 냉방 고장)

서버실 전체가 멈추는 1등급 상황입니다. 이때는 사람의 안전 → 데이터 보호(정상 종료) → 업무 연속(수기 전환) → 순서대로 복구의 순서를 지킵니다. 정전은 UPS가 버티는 시간(보통 10~30분) 안에 서버를 정상 종료해야 데이터가 깨지지 않으므로, 직원이 IT를 부르러 서버실에 오는 것보다 IT가 서버실에 집중할 수 있게 두는 것이 가장 큰 도움입니다.

4-2. IT 담당 조치와 복구 순서

서버는 서로 의존합니다. 네트워크와 AD가 없으면 ERP도 그룹웨어도 로그인할 수 없고, DB가 뜨기 전에 ERP 앱을 켜면 오류가 납니다. 그래서 종료는 아래 그림의 역순, 기동은 그림 순서대로 진행하며, 각 단계에서 정상을 확인한 뒤 다음 단계로 넘어갑니다.

5기타 장애 대응

서버 자체가 아니라 그 앞뒤(네트워크·회선·보안·개인 PC)에서 생기는 장애입니다. 겉으로는 “ERP가 안 된다”로 보여도 원인이 다르면 대응도 다릅니다.

5-1. 랜섬웨어 · 악성코드 감염 의심

30초 안에 할 세 가지: ① 랜선 뽑기(노트북은 Wi-Fi 끄기) ② 전원은 그대로 두기 ③ IT에 전화

파일 확장자가 낯선 것으로 바뀌고, 열리지 않으며, 바탕화면에 영문 협박 문구가 뜨면 랜섬웨어입니다. 랜선을 뽑으면 공유 폴더·문서중앙화로 번지는 것을 막을 수 있고, 전원을 유지하면 IT가 감염 경로를 분석할 수 있습니다.

대상해야 할 것하지 말 것
감염 의심 PC 사용자랜선 분리, IT 신고, 마지막으로 열었던 메일·파일·USB를 IT에 설명, 자리 이탈 시 PC에 “접근 금지” 메모.재부팅·포맷·백신 수동 실행·파일 삭제·USB로 파일 백업.
같은 부서 직원공유 폴더·문서중앙화 저장 잠시 중단(IT 안내까지), 의심 메일 삭제, 열려 있는 문서 로컬 저장.“나도 괜찮은지 보자”며 의심 파일 열기.

5-2. 피싱 · 계정 탈취 의심

“내가 보내지 않은 메일이 거래처에 갔다”, “로그인 알림이 낯선 곳에서 왔다”면 계정이 탈취된 것입니다. 즉시 IT에 알리고 IT 안내에 따라 비밀번호를 변경합니다(AD 장애 중에는 IT가 먼저 판단). 거래처 계좌 변경 요청 메일은 반드시 거래처 담당자에게 전화로 확인합니다. 회계팀은 계좌 변경 시 2인 확인 규정을 장애 중에도 유지합니다.

5-4. 인터넷 회선 장애 (사내 시스템은 정상)

ERP·문서중앙화는 되는데 외부 메일·홈택스·거래처 사이트·화상회의만 안 되면 인터넷 회선(통신사) 또는 방화벽 문제입니다.

  • 직원: 외부 업무는 스마트폰 핫스팟(테더링)으로 노트북을 연결해 처리합니다. 핫스팟 사용 중에는 사내 네트워크 랜선을 뽑아 두 망이 동시에 붙지 않게 합니다(보안 규정). 대용량 도면 전송은 회선 복구 후로 미룹니다.
  • 회계·영업: 홈택스·인터넷뱅킹·수출 서류는 핫스팟 노트북 1대를 부서 공용으로 지정해 처리합니다.
  • IT: 통신사 장애 접수(주회선·예비회선 번호 9장), 예비 회선(LTE 라우터·2차 ISP)으로 절체, 방화벽 세션·인증서·DNS 포워더 확인.

5-5. 개인 PC · 계정 장애 (4등급)

IT에 접수하기 전에 아래 세 가지만 확인하면 절반은 해결됩니다.

  1. 랜선(또는 Wi-Fi)·전원·모니터 케이블이 꽂혀 있는지 확인하고, PC를 완전히 껐다가 1분 뒤 켭니다(재시작이 아니라 종료 후 켜기).
  2. 옆자리 PC에서 같은 시스템이 되는지 확인합니다. 옆자리도 안 되면 개인 장애가 아니므로 부서장에게 알립니다.
  3. 계정이 잠겼다는 메시지면 15분간 로그인 시도를 멈춥니다(대부분 자동 해제). 비밀번호를 여러 번 틀려 반복 잠기면 IT 접수.

IT 접수 방법: 그룹웨어 「IT 요청」 게시판 → 안 되면 사내 단체방에 [PC장애] 부서/이름/증상 → 급하면 IT 내선. 접수 시 화면 사진을 같이 보냅니다. 업무가 급하면 부서 예비 PC(각 부서 1대 지정 권장)로 로그인해 일합니다.

5-6. 프린터 · 복합기 · 라벨 프린터

인쇄가 안 되면 ① 프린터 화면 오류(용지·토너·걸림) 확인 ② PC에서 인쇄 대기열 취소 ③ 다른 PC에서 출력 시도. 여러 사람이 동시에 안 되면 AD·네트워크 장애일 수 있으니 부서장에게 알립니다. 출하 라벨·LOT 라벨 프린터는 USB 직결 노트북 1대를 출하장·생산관리에 예비로 준비해 둡니다.

5-7. 전화 (IP 전화 · 인터넷 전화) 장애

대표번호와 내선이 안 되면 통신사 고객센터에서 대표번호를 총무팀 휴대폰으로 착신전환합니다(사전에 절차와 비밀번호를 총무팀이 보관). 영업 담당자는 주요 거래처에 휴대폰 번호를 문자로 안내합니다. 팩스 수신은 인터넷 팩스 서비스 또는 거래처에 메일 발송을 요청합니다.

8복구 후 사후 조치

복구 공지가 나가면 장애는 끝난 것이 아니라 “따라잡기”가 시작된 것입니다. 장애 중 수기로 처리한 업무를 순서대로 시스템에 넣지 않으면 재고·매출·결재 이력이 어긋납니다.

8-1. 직원 · 부서 체크리스트 (복구 후 24시간)

  • IT 공지의 “마지막 정상 저장 시각”을 확인하고, 그 이후에 처리한 업무 목록을 부서별로 작성한다.
  • ERP 입력 순서: 수주 → 작업지시 → 자재 입출고 → 생산 실적(MES) → 출하 → 세금계산서·회계. 앞 단계가 끝나야 뒤 단계를 입력한다.
  • 임시 번호(견적·작업지시·거래명세서)와 정식 번호의 대응표를 부서에 보관한다.
  • 수기 결재는 소급 상신하고 종이 원본을 첨부 스캔으로 붙인다.
  • 「장애임시」 폴더 파일을 문서중앙화·파일서버에 올리고, 로컬 사본은 7일 내 삭제한다.
  • 개인 메일로 주고받은 업무 메일은 사내 메일로 전달하고 개인 계정에서 회사 자료를 삭제한다.
  • 자재팀은 3일 내 주요 원자재·재공 실사를 하고 ERP 재고와 차이를 조정한다.
  • 부서장은 “장애 중 못 한 일·문제였던 점”을 한 줄씩 적어 IT에 보낸다(매뉴얼 개선 입력).

8-2. IT 담당 체크리스트

  • 모든 서비스 정상 확인(로그인·저장·메일 송수신·백업 잡 성공).
  • 장애 보고서 작성: 발생 시각·인지 경로·원인·영향 범위·조치·복구 시각·재발 방지책. 48시간 내 경영진 보고.
