# IMS 서버 모니터링 구축 순서

목표: 각 서버의 CPU / 메모리 / 디스크 / 네트워크를 IMS 웹화면에서 본다.
원칙: **새 포트를 외부에 열지 않는다.** 모든 통신은 IMS가 이미 쓰는 주소와 포트(80/443)로 들어온다.

```
[ERP 서버] agent ─┐                       IMS 서버
[MES 서버] agent ─┼─ http(s)://IMS주소/monitor/api/metrics ─▶ IMS 웹서버(IIS/nginx/Apache)
[파일 서버] agent ─┘                                              │  /monitor/ 만 내부로 전달
                                                                  ▼
                                                     수집기 node server.js (127.0.0.1:8787, 외부 접근 불가)
                                                                  ▲
[사용자 브라우저] ── IMS 로그인 → 서버 모니터링 메뉴 (iframe /monitor/) ┘
```

8787 은 IMS 서버 **내부에서만** 쓰는 번호이고 방화벽에 열지 않는다. 사용자도 에이전트도 IMS 주소만 안다.

---

## 0단계. 사전 조사 (반나절)

아래를 표로 정리한다. 이 표가 이후 모든 단계의 입력이다.

| 항목 | 확인 방법 | 예 |
|---|---|---|
| IMS 서버 OS | 원격 접속 후 `winver` / `cat /etc/os-release` | Windows Server 2019 |
| IMS 웹서버 종류 | IIS 관리자가 있으면 IIS. 아니면 `nginx -v`, `httpd -v`, 톰캣 폴더 | IIS 10 |
| IMS 접속 주소 | 사용자가 브라우저에 치는 주소 | http://ims.회사.co.kr 또는 http://192.168.1.50 |
| http 인지 https 인지 | 주소창 자물쇠 | http |
| 모니터링 대상 서버 목록 | 서버명, IP, OS, 역할(ERP/MES/DB/파일/AD), 담당자 | 8대 |
| 서버 대역 → IMS 서버 80/443 통신 가능 여부 | 대상 서버에서 브라우저로 IMS 주소 열어보기 | 가능 |

마지막 항목이 안 되면 네트워크 담당자에게 "서버 대역에서 IMS 서버 80(443) 허용"을 요청한다. 대부분 이미 열려 있다.

## 1단계. IMS 서버에 수집기 설치 (1시간)

IMS 서버에 원격 접속해서 진행한다.

1. Node.js LTS 설치. https://nodejs.org 에서 받아 기본값으로 설치. 설치 후 새 터미널에서 `node -v` 확인.
2. `monitor` 폴더를 IMS 서버로 복사. 권장 위치: `C:\ims\monitor` (Windows) / `/opt/ims/monitor` (Linux).
3. 토큰을 하나 정한다. 아무 문자열이나 되며 에이전트도 같은 값을 쓴다. 예: `ilsan-mon-2026`
4. 수집기를 상시 실행으로 등록한다.

   Windows (관리자 PowerShell):
   ```
   cd C:\ims\monitor
   Set-ExecutionPolicy -Scope Process Bypass
   .\deploy\install-collector-windows.ps1 -Token ilsan-mon-2026
   ```
   Linux:
   ```
   cd /opt/ims/monitor
   sudo TOKEN=ilsan-mon-2026 ./deploy/install-collector-linux.sh
   ```
5. 확인. IMS 서버 안에서 브라우저로 `http://127.0.0.1:8787/` 을 열면 빈 대시보드가 뜬다. 화면 오른쪽 위 "수집기 vX.Y.Z" 가 새로 설치한 버전과 같은지 본다.
   **재설치/업그레이드**: `monitor` 폴더를 덮어쓴 뒤 설치 스크립트를 다시 실행하면 기존 수집기 프로세스를 종료하고 새 버전으로 교체한다. 버전 표시가 안 바뀌면 예전 node.exe 가 남아 있는 것이니 작업 관리자에서 node.exe 를 끝내고 다시 실행한다.
   다른 PC에서는 열리지 않는 것이 정상이다 (내부 전용).

## 2단계. IMS 웹서버에 /monitor/ 프록시 설정 (30분)

IMS 웹서버가 `/monitor/` 로 오는 요청만 내부 수집기(127.0.0.1:8787)로 넘겨주게 한다.
0단계에서 확인한 웹서버 종류에 맞는 것 하나만 한다.

**IIS**
1. URL Rewrite 와 Application Request Routing(ARR) 모듈을 설치한다. (Microsoft 사이트에서 무료 다운로드, 재부팅 불필요)
2. IIS 관리자 > 서버 노드 > Application Request Routing Cache > 오른쪽 Server Proxy Settings > Enable proxy 체크 > 적용.
3. IMS 사이트의 `web.config` 에 `deploy/iis-web.config` 의 `<rewrite>` 부분을 넣는다. 이미 `<rewrite>` 가 있으면 `<rule>` 만 추가.

**nginx**: `deploy/nginx.conf` 의 `location` 두 개를 IMS `server { }` 블록에 넣고 `nginx -t && nginx -s reload`.

**Apache**: `deploy/apache.conf` 내용을 VirtualHost 에 넣고 재시작. `proxy`, `proxy_http` 모듈 필요.

**IMS 가 자체 포트로 직접 뜨는 애플리케이션인 경우** (예: `http://192.168.0.9:15137/` 처럼 IIS/nginx 없이 앱이 포트를 여는 구조)
프록시를 넣으려면 IMS 코드를 고쳐야 하므로, 1차는 수집기를 **IMS 옆 포트**로 직접 연다. IMS 가 이미 비표준 포트를 쓰고 있으니 하나 더 여는 것은 같은 관리 방식이다.

1. 1단계 설치를 `-Public -Port 15138` 로 한다 (IMS 포트 + 1). 방화벽 규칙이 자동 추가된다.
   가장 쉬운 방법: `deploy\setup-collector.cmd` 의 PORT/TOKEN 을 확인하고 **더블클릭**.
   명령으로 하려면:
   ```
   .\deploy\install-collector-windows.ps1 -Public -Port 15138 -Token 정한토큰
   ```
2. 이후 단계의 주소는 `http://192.168.0.9:15138/...` 이 된다.
   - 에이전트: `-Url http://192.168.0.9:15138/api/metrics`
   - 확인: `http://192.168.0.9:15138/api/health`
   - IMS 메뉴 iframe: `http://192.168.0.9:15138/?embed=1&theme=light`
3. 나중에 IMS 앱에 `/monitor/` 프록시 라우트를 추가하면 (Express, Spring, ASP.NET 모두 몇 줄) 15138 을 닫고 한 포트로 합칠 수 있다.

확인: 다른 PC 브라우저에서 `http://IMS주소/monitor/` 를 열면 대시보드가 뜬다. `http://IMS주소/monitor/api/health` 는 `{"ok":true,...}` 를 보여준다.

## 3단계. 첫 서버 한 대에 에이전트 설치 (10분)

가장 덜 중요한 서버부터. 에이전트는 읽기만 하고 서버에 아무것도 바꾸지 않는다.

**Windows 서버: 설치 프로그램 실행**
1. `dist\IMS-Monitoring-Agent-Setup.exe` 를 서버로 복사해서 실행한다 (관리자 확인 "예").
2. 설정 화면에서 전송 주소 `http://192.168.0.9:15138/api/metrics` 와 토큰(1단계에서 정한 값)을 입력하고 다음 → 설치.
3. 설치가 끝나면 작업 표시줄 트레이에 아이콘이 생긴다. 오른쪽 아래 점이 **초록 = 정상 전송, 빨강 = 전송 실패, 회색 = 에이전트 중지됨**. 두 번 클릭하면 모니터링 화면이 열린다.
   우클릭 메뉴: 상태 보기 / 이름 설정 / 모니터링 화면 열기 / 로그 보기 / 에이전트 시작 / 에이전트 종료(전송 중지) / 트레이 아이콘 닫기.
   **이름 설정**에서 "ERP 서버" 처럼 표시 이름을 넣으면 모니터링 화면에 그 이름이 크게, 호스트명은 작게 표시된다. 비우면 호스트명으로 돌아간다.
   바탕화면과 시작 메뉴에 "IMS Monitoring Agent" 아이콘이 생긴다. 실행하면 멈춰 있던 에이전트를 시작하고 트레이 아이콘을 띄운다.
4. 설치 프로그램이 하는 일: `C:\Program Files\IMSMonitoringAgent` 에 파일 복사, 작업 스케줄러에 시스템 시작 시 자동 실행 등록(SYSTEM, 죽으면 1분 뒤 재시작), 로그온 시 트레이 아이콘 자동 실행, [프로그램 추가/제거] 등록.
5. 제거: [설정 > 앱] 또는 [프로그램 추가/제거] 에서 "IMS Monitoring Agent" 제거. 제거하면 수집기에 알려서 모니터링 화면에서도 카드가 사라진다. 로그는 `C:\ProgramData\IMSMonitoringAgent\agent.log`.

재설치하면 기존 주소/토큰이 자동으로 채워진다. 설치 프로그램은 `agent/win/build.sh` 로 다시 빌드할 수 있다 (NSIS 필요). 아이콘은 `agent/win/make-icon.py` 가 생성한다.

**Linux 서버**: `agent/linux` 폴더의 두 파일을 서버로 복사한 뒤
```
chmod +x install.sh
sudo ./install.sh --url http://192.168.0.9:15138/api/metrics --token ilsan-mon-2026 --name "리눅스 서버"
```
`ims-agent` 서비스로 등록된다. 이후 `ims-agent status`, `sudo ims-agent name "이름"`, `sudo ims-agent disks "/,/data"`(화면에 보일 마운트, 기본은 시스템 파티션 자동 제외), `sudo ims-agent restart`, `ims-agent log`, `sudo ims-agent uninstall`(화면에서도 자동 제거). https 사설 인증서면 `--insecure` 추가.

**시놀로지 NAS**: 제어판 → 터미널 및 SNMP 에서 SSH 를 켜고 위와 같이 설치한다. systemd 가 없으므로 스크립트가 백그라운드로 띄우고, 부팅 시 자동 실행은 스크립트가 안내하는 대로 DSM 작업 스케줄러(트리거된 작업 → 부팅 → root → `/usr/local/bin/ims-agent start`)에 등록한다. 볼륨(`/volume1` 등) 용량과 CPU/메모리가 서버와 같은 카드로 보인다. 물리 디스크 건강 상태는 이 방식으로는 안 보이므로 DSM 자체 알림을 함께 쓴다.
**VMware ESXi 가상화 호스트**: 일반 리눅스가 아니라(bash · systemd · /proc 없음) `agent/esxi` 의 전용 에이전트를 쓴다. ESXi 내장 python 과 vim-cmd/esxcli 로 CPU · 메모리 · 데이터스토어 · 가동시간을 읽는다. ESXi 호스트 클라이언트에서 SSH 를 켠 뒤 `ims-agent-esxi.py`, `install.sh` 를 올리고:
```
cd /ims && chmod +x install.sh
./install.sh --url http://192.168.0.9:15138/api/metrics --token ilsan-mon-2026 --name "가상화 서버"
```
첫 VMFS 데이터스토어의 `ims-agent` 폴더에 설치되고 `/etc/rc.local.d/local.sh` 로 부팅 시 자동 실행된다. 관리: `<데이터스토어>/ims-agent/ims-agent status|name|restart|log|uninstall`. 안의 가상 서버들은 각각 Windows/Linux 에이전트로 본다.
**ipTIME NAS**: 전용 펌웨어라 에이전트를 설치할 수 없다. 다른 서버의 에이전트가 공유폴더 응답과 용량을 대신 읽어 올리는 방식으로 대체 가능 (미구현).

확인: `http://192.168.0.9:15138/` 에 그 서버 카드가 뜬다. 서버를 재부팅해도 다시 뜨면 등록 완료.

문제가 생기면 서버에서 직접 확인:
- 트레이 아이콘이 빨강이면 우클릭 > 상태 보기 에서 실패 원인이 나온다. "(401) 권한이 없음" 이면 토큰 불일치: IMS 서버 `deploy\setup-collector.cmd` 의 TOKEN 과 에이전트 설치 시 입력한 토큰이 다른 것. 수집기 창 로그에도 "토큰 불일치" 가 찍힌다. ZIP 을 다시 받아 덮어쓰면 setup-collector.cmd 의 토큰이 기본값으로 돌아가니 주의.
- `Invoke-WebRequest http://192.168.0.9:15138/api/health` → 응답 오면 네트워크는 정상, 토큰 불일치 가능성.
- 응답이 없으면 서버 대역 ↔ IMS 서버 15138 방화벽 문제.
- 재부팅 뒤 트레이가 "에이전트 응답 없음"이면 우클릭 > **에이전트 재시작**. 에이전트 1.3.0 부터는 부팅 30초 뒤 시작하고 성능 카운터 대신 WMI 로 CPU 를 읽어 이 현상이 나지 않는다.

**가동 시간 기준**: Windows 가 켜진 시점부터 계산한다. Windows 10 PC 는 "빠른 시작" 때문에 OS 부팅 시각이 갱신되지 않을 수 있어, 에이전트는 시스템 로그의 시작 이벤트(Kernel-Boot 27)도 함께 봐서 더 최근 시각을 쓴다. 서버에서는 두 값이 같다.

## 4단계. 나머지 서버 확장 (서버당 10분)

3단계를 서버마다 반복한다. 0단계 표에 설치일과 결과를 적어 둔다.
DB 서버 등 중요한 서버는 업무 시간 외에 하고, 설치 직후 5분간 CPU 에 영향이 없는지 본다 (에이전트 자체 부하는 1% 미만).

## 5단계. IMS 메뉴에 붙이기 (IMS 개발, 1~2시간)

IMS 에 "서버 모니터링" 메뉴를 하나 만들고 페이지에 한 줄 넣는다.
```html
<iframe src="/monitor/?embed=1&theme=light" style="width:100%;height:720px;border:0"></iframe>
```
IMS 로그인한 사용자만 이 메뉴에 들어오므로 권한은 IMS 체계를 그대로 쓴다.
IMS 스타일로 요약 숫자만 보여주고 싶으면 `deploy/embed-sample.html` 처럼 `/monitor/api/servers` 를 호출해 직접 그린다.

이 단계까지가 **1차 오픈**이다.

## 6단계. 운영 보강 (1차 오픈 후)

- **임계치 알림 (텔레그램)**: 아래 "알림 설정" 절차 참고. 화면 오른쪽 위 🔔 알림 버튼에서 설정한다.
- **장기 이력 보관**: 현재는 최근 1시간 + 재시작 대비 스냅샷. 월 단위 추이가 필요하면 IMS DB 에 저장하는 방법 B 로 전환.
- **방법 B (IMS 안으로 흡수)**: IMS 애플리케이션에 `POST /api/metrics` 수신과 테이블을 추가하면 Node 수집기가 필요 없어진다. 에이전트는 전송 주소만 바꾸면 된다.
- **모니터링 서버 자체 감시**: IMS 서버가 죽으면 이 화면도 죽는다. 외부에서 IMS 를 ping 하는 간단한 체크를 하나 둔다.

## 로그인 · 홈 화면 · 계정 관리 (수집기 1.15.0+)

주소(`http://192.168.0.9:15138/`)로 들어가면 **로그인 화면**이 먼저 뜨고, 로그인하면 **홈 화면**에서 갈 곳을 고른다.

- 처음 계정: **admin / rhksflwk1@** (수집기를 처음 실행할 때 `data/users.json` 에 자동으로 만들어진다). 로그인 후 계정 관리에서 비밀번호를 바꿀 수 있다.
- **홈 화면**(`/home.html`): 서버 모니터링 · 일정 관리(준비 중) · 계정 관리(관리자만) 타일. 화면이 늘어나면 타일이 자동으로 늘어난다.
- **계정 관리**(`/users.html`, 관리자만): 계정 만들기 · 수정 · 삭제, 계정마다 볼 수 있는 화면을 체크로 지정.
  - **"최초 로그인 시 비밀번호 변경"** 을 체크(새 계정은 기본 켜짐)하면, 그 사람이 아이디와 임시 비밀번호로 로그인하는 순간 **비밀번호 변경 창이 바로 뜨고, 바꿔야만 들어갈 수 있다.** 계정 목록에 "비밀번호 변경 대기" 로 표시된다.
  - 비밀번호 규칙: **4자 이상, 아이디와 똑같이 정할 수 없음**(대소문자 무시), 지금 쓰는 비밀번호와 달라야 함. 관리자가 계정을 만들 때 넣는 임시 비밀번호에도 같은 규칙이 적용된다.
  - 비밀번호를 잊은 사람은 관리자가 계정 수정에서 새 비밀번호를 넣고 이 체크를 켜서 알려 주면 된다.
  - 누구나 상단의 **"비밀번호"** 버튼(홈 화면은 "비밀번호 변경")으로 자기 비밀번호를 언제든 바꿀 수 있다. "관리자" 를 켜면 모든 화면 + 계정 관리까지 쓸 수 있다.
  - 관리자가 한 명도 남지 않게 되는 삭제·수정은 막혀 있고, 지금 로그인한 계정은 지울 수 없다.
- 로그인 상태는 12시간 유지된다. 로그인 화면에서 **"이 컴퓨터에서 로그인 유지"** 를 켜면 30일 — IT실 TV 상황판(`/dashboard.html?tv=1`)처럼 계속 띄워 두는 화면은 이 체크를 켜고 한 번 로그인해 두면 된다.
- 계정은 `data/users.json` 에 저장되므로 수집기를 새 버전으로 덮어써도 유지된다.
- **비밀번호를 모두 잊었을 때**: IMS 서버에서 `C:\ims\monitor\data\users.json` 을 지우고 `deploy\setup-collector.cmd` 를 다시 실행하면 admin / rhksflwk1@ 로 초기화된다.
- 에이전트 전송(`/api/metrics`)은 로그인과 무관하게 토큰으로만 확인하므로, 로그인을 걸어도 서버 수집은 그대로 돌아간다.

## 일정 관리 (수집기 1.16.0+)

홈 화면 → **일정 관리**. 부서별 업무 일정을 등록하고 진행 상황을 기록한다. 저장 위치는 `data/schedule.json` 이라 수집기를 덮어써도 유지된다.

- **개인 일정이 기본이다.** 등록할 때 "팀 공유" 를 체크하지 않으면 **나만 보는 일정**이다. 다른 사람은 관리자라도 볼 수 없고 수정할 수도 없다. 체크하면 같은 부서 사람들이 본다. 목록에서 팀 공유 일정에는 회색 "팀" 표가 붙는다.
- **보기 다섯 가지**: **할 일**(기본 화면 — 오늘 · 앞으로 7일 · 밀린 일을 메모까지 펼쳐서 보여 준다), **월**(달력), **주**(요일별 카드), **타임라인**(한 달, 일정마다 한 줄인 간트), **연간**(1년, 가로 12개월 · 반복 일정은 달마다 횟수 표시). 위쪽 ◀ ▶ 로 앞뒤 기간을 본다.
- **할 일 화면**에서는 카드 아래 예정·진행·완료·보류 버튼을 눌러 바로 상태를 바꿀 수 있다. 완료로 바꾸면 밀린 일 목록에서 사라진다.
- **등록**: 오른쪽 위 "+ 일정 등록", 또는 달력에서 날짜 칸에 마우스를 올리면 나오는 ＋ 를 누르면 그 날짜로 바로 열린다.
- **항목**: 제목, 부서, 담당자, 시작·종료 날짜, 시간(선택), 상태(예정·진행·완료·보류), **중요도(보통·중요·긴급)**, 반복(안 함·매주·매월·매년), 내용. 담당자는 로그인한 사람 이름이 기본으로 들어간다 (고칠 수 있음).
- **공휴일**: 한국 공휴일이 달력·주·타임라인에 빨간 글씨로 나온다. 2026~2027년이 기본으로 들어 있고, **음력 명절·대체공휴일·임시공휴일은 정부 공고에 따라 달라질 수 있으므로 반드시 확인하고 "공휴일 관리"(관리자만)에서 고친다.** "공휴일 관리" 창에서 연도를 넘겨 가며 목록을 보고, 날짜를 고르고 이름을 적어 "추가", 필요 없는 날은 "지우기", 마지막에 "저장" 을 누른다. 창립기념일 같은 회사 휴무일도 같은 방법으로 넣으면 달력에 표시된다.
- **일정 클릭** → 등록 창과 같은 모양의 팝업이 열린다. 맨 위에 부서·중요도·공개(팀 공유/나만 보기)·반복·날짜가 표시되고, 그 아래 버튼으로 상태를 바꾼다. 왼쪽에서 내용을 고치고 오른쪽 아래에서 메모를 쌓는다. 메모는 누가 언제 적었는지 같이 남는다. 삭제도 이 창에서 한다.
- 시작·종료 날짜는 **오늘 날짜가 기본**으로 들어가고, 날짜 칸을 **두 번 누르면 달력이 열린다**.
- **반복 일정**: 원본 하나만 저장하고 화면에서 펼쳐 보여 준다. 상태와 메모는 **그 날짜에만** 기록되므로 "매주 서버 점검" 한 건으로 매주 완료 여부를 따로 남길 수 있다. 하루만 건너뛰려면 "이 날짜만 빼기".
- **필터**: 부서 · 담당자 · 상태. 위쪽 요약(전체·진행 중·완료·예정·기한 지남)도 필터를 따라간다.
- **부서 목록**은 홈 → **계정 관리** 화면 맨 위 "부서 관리" 에서 고친다 (기본: 지원팀·생산팀·영업팀·관리팀·품질팀). 부서마다 그 부서를 보도록 지정된 인원 수가 같이 나온다.
### 팀별로 따로 보기 (다른 팀 일정은 아예 안 보이게)

계정 관리(관리자) → 계정 수정 → **"일정에서 볼 수 있는 부서"** 에서 그 사람의 팀만 체크한다.

- 이것은 **팀 공유 일정**에만 해당한다. 개인 일정은 부서와 상관없이 만든 사람만 본다.
- 체크한 부서의 팀 공유 일정만 화면에 나온다. 다른 팀 일정은 목록·달력·통계 어디에도 나오지 않고, 주소를 직접 쳐도 수집기가 내려 주지 않는다 (화면에서 숨기는 것이 아니라 서버에서 걸러진다).
- 그 사람이 일정을 등록할 때 부서도 자기 팀으로만 고를 수 있다.
- 하나도 체크하지 않으면 모든 부서를 본다. **관리자는 항상 전체를 본다.**
- 여러 팀을 함께 봐야 하는 사람(예: 팀장, 경영진)은 필요한 부서를 여러 개 체크한다.
- 예: 지원팀 직원 계정 → 화면 권한 "일정" 체크 + 부서 "지원팀"만 체크.

계정 관리에서 "일정" 화면 권한을 준 사람만 이 화면을 볼 수 있다. 볼 수 있는 사람은 등록·수정도 할 수 있다. 부서 목록과 공휴일 고치기는 관리자만 할 수 있다.
- 고지서 화면은 다음 단계에서 별도 화면으로 만든다.

## Veeam 백업 상태 모니터링

Veeam Backup & Replication 서버에 에이전트 1.4.0 이상을 설치하면(기존 에이전트 위에 덮어쓰기), 에이전트가 10분마다 Veeam 작업 상태를 읽어 같이 보낸다. 추가 설치나 설정은 없다.
- 서버 현황: Veeam 서버 카드에 "💾 백업 5/6 성공 · 실패 1" 요약줄, 카드를 클릭하면 작업별 결과·마지막 실행·마지막 성공·소요·크기·다음 실행과 저장소 용량 표.
- 대시보드: "백업 현황" 패널에 실패·경고가 위로 오도록 정렬.
- 알림(🔔 알림 설정 → "백업 알림"): 작업 실패/경고, 마지막 성공 후 N시간(기본 26) 넘게 성공 없음, 저장소 사용률이 디스크 기준(기본 90%) 이상. 판단은 "백업 점검 시각"(기본 08:00, 새벽 백업이 끝난 뒤)에 하루 한 번만 하고, 비우면 10분마다 계속 판단한다. 화면 표시는 시각과 관계없이 계속 갱신된다. 서버 팝업의 "이 서버 알림 › 백업" 으로 서버별로 끌 수 있다.
- 안 나올 때: Veeam 서버의 `C:\ProgramData\IMSMonitoringAgent\agent.log` 에서 `[Veeam]` 줄 확인. "모듈 없음"이면 Veeam 콘솔이 설치된 서버가 아니거나 PowerShell 모듈이 빠진 것. 권한 오류면 Veeam 콘솔 → Users and Roles 에 로컬 관리자(SYSTEM 포함) 추가. `veeam.json` 이 3시간 이상 오래되면 보내지 않는다.

## SQL 백업 · USB 백업 감시 (3단계 백업)

에이전트 1.5.0 이상을 SQL 백업이 있는 서버(ERP 부산·김해, 그룹웨어, ACE ERP)에 덮어쓰기 설치하면 추가 설정 없이 동작한다.
- **1차 SQL**: `D:\DBBackup`, `D:\DB_BACKUP` 같은 폴더를 자동으로 찾아 최신 백업 파일 시각·개수·용량을 보내고, SQL Server 기록(msdb)에서 DB별 마지막 전체/차등/로그 백업 시각도 읽는다. 다른 경로면 `agent.conf` 에 `BACKUP_PATH=D:\백업;E:\백업2` 를 적는다. SQL 기록 조회가 권한 오류면 SQL Server 에서 `NT AUTHORITY\SYSTEM` 로그인에 msdb 읽기(db_datareader)를 주거나 `SQL=0` 으로 끄면 폴더 기준으로만 본다.
- **3차 USB**: 알림 설정의 "USB 확인 시간대"(기본 07:00-10:00) 안에서만 USB 를 살핀다 (값은 각 에이전트에 자동 전달). USB 디스크가 꽂혀 있는 동안 5분마다 확인해서 복사본의 최신 파일 시각과 남은 용량을 기억한다. USB 를 빼도 마지막 값을 계속 보낸다.
- **USB 백업 폴더 지정** (에이전트 1.6.0, 수집기 1.14.0): 서버 현황에서 서버를 클릭 → "3차 백업(USB)" 표 아래 **USB 백업 폴더** 칸에 bat 가 복사하는 대상 폴더를 적고 저장하면 5초 안에 그 서버 에이전트에 전달된다 (서버마다 다르게). 비우면 자동 감지(USB 안의 backup/bak/db 폴더 중 하나를 고르므로 엉뚱한 폴더가 잡혀 "743일 전" 처럼 뜰 수 있음).
  - 가장 쉬운 방법: bat 의 xcopy 대상에서 드라이브 문자를 뺀 폴더만 적는다. 예 `0.백업\1.ERP(부산)\DBBackup`. 에이전트가 꽂혀 있는 USB 를 모두 뒤져 그 폴더가 있는 드라이브를 쓰므로 드라이브 문자가 바뀌어도 된다. USB 가 안 꽂혀 있으면 "USB 가 꽂히면 … 폴더를 확인" 으로 표시되며 오류가 아니다.
  - 파일이 아주 많은 폴더(그룹웨어 data 증분 백업 등)는 에이전트가 자동으로 알아채서(2단계까지 항목 3000개 초과, 또는 훑는 데 20초 초과) 파일을 세지 않고 폴더 시각만 확인한다. 화면에는 파일 수가 "많음"으로 뜨고 복사 시각은 폴더가 바뀐 시각이다. 강제로 정하려면 항목 뒤에 `|빠름` 또는 `|전체` 를 붙인다 (예 `DATA=0.백업\data|빠름`).
  - 드라이브 문자로: `E:\DBBackup`
  - USB 가 두 개(그룹웨어: data 용, db 용): `DB=E:\DB_BACKUP; DATA=F:\GWData` 처럼 `이름=경로` 를 `;` 로 나열하면 카드·팝업·대시보드·백업 탭에 "3차 백업(USB) · DB", "3차 백업(USB) · DATA" 로 따로 뜨고 알림도 따로 간다.
  - 드라이브 문자가 바뀌는 USB 는 라벨로: `ERP_Bcakup:\DBBackup` (탐색기에 보이는 USB 이름). 
  - bat 에 usb-done.ps1 줄을 넣었으면 그 경로와 같은(또는 상위/하위) 폴더의 USB 에 복사 결과가 붙는다. USB 두 개면 각 bat 에 각각 넣는다.
  - `agent.conf` 에 `USB=E:\DBBackup` 을 적으면 화면 설정보다 우선한다 (예전 방식).
- USB 가 몇 분 만에 자동 분리되는 경우: 에이전트가 새 드라이브가 꽂히는 순간(5초 이내) 감지해 4분 동안 20초마다 확인하므로 대부분 잡힌다. 더 정확히 하려면 복사 bat 파일의 robocopy 줄 **바로 다음, 분리(eject) 전**에 아래 한 줄을 넣는다. 복사 완료 시각과 robocopy 결과(0~7 정상, 8 이상 실패)가 그대로 기록되어 화면에 "복사 완료 09:12"로 뜨고 실패면 알림이 간다.
  ```
  powershell -NoProfile -ExecutionPolicy Bypass -File "C:\Program Files\IMSMonitoringAgent\usb-done.ps1" %ERRORLEVEL%
  ```
  bat 에서 USB 를 `%USB%` 변수로 잡고 xcopy 하는 경우는 대상 폴더와 xcopy 를 그대로 적는다 (USB 가 3분 만에 빠져도 이 기록으로 "복사 완료 09:12 (코드 0)" 가 뜬다):
  ```
  powershell -NoProfile -ExecutionPolicy Bypass -File "C:\Program Files\IMSMonitoringAgent\usb-done.ps1" %ERRORLEVEL% "%USB%\0.백업\1.ERP(부산)\DBBackup" xcopy
  ```
  이 줄은 xcopy 바로 다음 줄에 넣어야 `%ERRORLEVEL%` 이 xcopy 결과가 된다. 화면의 USB 백업 폴더 설정과 폴더 이름이 같으면 자동으로 짝지어진다.
- 카드에 "💾 1차 SQL 6시간 전 / 3차 USB 어제" 식으로 단계별 줄이 생기고, 클릭하면 표가 나온다. 대시보드 "백업 현황"에도 단계 행이 올라간다.
- 알림은 백업 점검 시각(기본 08:00)에 하루 한 번: SQL 백업 파일이 26시간(설정) 넘게 없음, DB 전체 백업이 오래됨, USB 복사본이 30시간(설정) 넘게 없음, USB 남은 용량 10% 미만. "주말은 백업 없음"이 켜져 있으면 토·일 시간은 경과 시간에서 빼므로 월요일 아침에 오알림이 나지 않는다.

## 에이전트가 저절로 꺼질 때 (Windows Server 2012, 구버전 백신)

에이전트 1.3.1 부터는 5분마다 도는 감시자 작업(`IMSMonitoringAgentWatchdog`)이 에이전트가 죽었거나 3분 이상 멈춰 있으면 자동으로 다시 시작하고, `C:\ProgramData\IMSMonitoringAgent\agent.log` 에 `[감시자] ... -> 다시 시작` 으로 남긴다. 원인 확인은 다음 순서로.
1. 작업 스케줄러 → `IMSMonitoringAgent` → 기록 탭: "작업이 실행 시간 제한을 초과" 가 있으면 2012 의 실행 시간 제한 버그 (1.3.1 설치 시 자동 해제. 수동으로는 속성 → 설정 → "작업이 다음 시간 이상 실행되면 중지" 체크 해제).
2. 백신 로그에 `powershell.exe` 차단/치료 기록이 있으면 백신 예외에 `C:\Program Files\IMS Monitoring Agent\` 폴더와 `powershell.exe` 를 추가.
3. `agent.log` 마지막 줄이 오류로 끝나면 그 내용을 확인 (WMI 오류 등).

## 알림 설정 (텔레그램)

- **오프라인 유예**: 알림 설정의 "오프라인 유예 (분)"에 예를 들어 5 를 넣으면, 응답 없음이 5분 안에 복구될 때 텔레그램을 보내지 않고 이력에만 "알림 생략"으로 남긴다. 새벽 백업 중 잠깐 끊기는 서버가 있을 때 사용. 0 이면 지금처럼 90초 무응답 즉시 전송.
- **알림 소리 종류**: 상단 🔊 → "소리 종류"에서 알림음 / 음성 / 둘 다. 음성은 "ACE ERP 서버 오프라인"처럼 서버 이름과 내용을 읽어 준다 (Windows 의 한국어 음성 사용, Chrome·Edge).

수집기가 10초마다 규칙을 검사해서 경고를 만들고, 텔레그램 봇으로 휴대폰에 보낸다. 화면이 열려 있는 PC 에는 상단 빨간 배너와 브라우저 알림도 뜬다.

**끄고 켜기**
- 🔔 알림 창 맨 위 "알림 사용"에서 전체 알림, CPU / 메모리 / 디스크 / 오프라인 알림을 각각 끌 수 있다.
- 특정 서버만 끄려면 카드를 클릭해 "🔕 이 서버 알림 끄기". 카드에 🔕 가 붙고 그 서버는 어떤 알림도 만들지 않는다.
- 서버별로 종류만 끄려면 카드 팝업의 "이 서버 알림: CPU / 메모리 / 디스크 / 오프라인" 체크를 끈다. (예: SQL 서버는 메모리만 끄기)
- **디스크 점검 시각** (기본 11:30): 디스크 사용률·소진 예상 알림은 하루 한 번 이 시각에만 판단하고, 전일/7일/30일 비교용 일별 값도 이 시각 값으로 고정한다. 새벽 백업으로 용량이 부풀었다가 아침에 정리되는 서버에서 헛알림을 막기 위한 것. 비우면 5초마다 계속 감시한다.

**기본 규칙** (🔔 알림 창에서 변경 가능)
- CPU 80% 이상이 1분 이상 지속 / 메모리 90% 이상이 1분 이상 지속
- 디스크 90% 이상 / 예상 소진 30일 이내
- 오프라인 (90초 무응답)
- 경고가 계속되면 60분마다 재알림, 정상으로 돌아오면 복귀 알림
- 조용 시간을 켜면 그 시간에는 텔레그램을 보내지 않는다 (오프라인 알림은 예외). 이력에는 남는다.

**텔레그램 봇 만들기 (5분, 휴대폰에서)**
1. 텔레그램 앱에서 `@BotFather` 를 검색해 대화를 연다.
2. `/newbot` 입력 → 봇 이름(예: `ILSAN IMS 모니터`) → 봇 아이디(예: `ilsan_ims_monitor_bot`, 반드시 `bot` 으로 끝남) 입력.
3. BotFather 가 주는 **토큰**(`123456789:AAH...` 형태)을 복사한다. 이 토큰은 비밀번호와 같으니 외부에 공개하지 않는다.
4. 방금 만든 봇을 검색해서 대화를 열고 **아무 메시지나 하나 보낸다** ("안녕"). IT팀 여러 명이 받으려면 그룹을 만들어 봇을 초대하고 그룹에서 메시지를 하나 보낸다.

**수집기에 연결 (모니터링 화면에서)**
1. `http://192.168.0.9:15138/` 오른쪽 위 **🔔 알림** 클릭.
2. 봇 토큰 붙여넣기 → **채팅 ID 찾기** 클릭 → 목록에서 본인(또는 그룹) 선택.
3. **테스트 전송** 클릭 → 휴대폰에 "테스트" 메시지가 오면 성공. "텔레그램으로 알림 보내기" 체크 확인 후 **설정 저장**.
4. 화면을 항상 띄워두는 PC 가 있으면 **이 브라우저 알림 켜기**도 눌러 둔다.

**안 될 때**
- "텔레그램 연결 시간 초과 / 인터넷 차단": IMS 서버에서 `api.telegram.org` 로 나가는 443 이 막혀 있다. 네트워크 담당자에게 IMS 서버의 해당 주소 아웃바운드 허용을 요청한다.
- "봇 토큰이 잘못되었습니다": BotFather 토큰을 다시 복사한다. 앞뒤 공백이 들어가기 쉽다.
- "대화가 없습니다": 봇에게 먼저 메시지를 보내야 채팅 ID 를 찾을 수 있다.
- 설정은 IMS 서버의 `C:\ims\monitor\data\settings.json` 에 저장된다. 토큰은 화면에는 마스킹되어 표시된다.
- 알림 이력은 화면에 최근 10건만 보이고, 전체는 `C:\ims\monitor\data\alerts-YYYY-MM.log` 에 월별 텍스트로 쌓인다. 🔔 알림 창 아래에서 월을 골라 "전체 이력 보기"(새 탭) 또는 "텍스트 파일 다운로드"로 받을 수 있다.

## 데이터 백업과 복구 (수집기 1.18.0+)

프로그램 자체는 GitHub 에 있으므로 다시 받으면 되지만, **`monitor\data` 폴더는 이 서버에만 있는 자료**다. 계정·비밀번호, 일정과 메모, 알림 설정(텔레그램 토큰 포함), 서버 목록과 구성도, 디스크·통계 이력, 백업 이력, 알림 로그가 모두 여기 있다.

### 자동 백업 (설치하면 자동으로 등록됨)

`deploy\setup-collector.cmd` 를 실행하면 작업 스케줄러에 **ServerMonitorBackup** 작업이 매일 03:10 으로 등록된다. 하는 일은 두 가지다.

| 저장 위치 | 내용 |
|---|---|
| `백업폴더\daily\2026-09-16\` | data 폴더(json·로그)를 날짜별로. 30일 지나면 자동 삭제 |
| `백업폴더\full\` | 프로그램 전체 한 벌. 이 폴더만 통째로 복사하면 바로 복구됨 |

- 기본 저장 위치는 `C:\ims\monitor-backup` 이다. **같은 디스크에 두면 디스크가 죽을 때 같이 죽으므로, 다른 디스크나 NAS 로 바꾸는 것을 권한다.**
- 바꾸는 방법: `monitor\deploy\backup-target.txt` 파일을 만들고 경로 한 줄만 적는다 (예: `D:\ims-monitor-backup`). 또는 설치할 때 `-BackupDir "경로"` 를 준다.
- **NAS 공유 폴더(`\\192.168.0.238\...`)로 보내려면** 작업 스케줄러에서 `ServerMonitorBackup` 작업의 실행 계정을 NAS 에 접근되는 계정으로 바꿔야 한다. 기본 SYSTEM 계정은 공유 폴더에 접근하지 못한다. 번거로우면 로컬(D 드라이브 등)에 백업하고, 그 폴더를 **Veeam 으로 함께 백업**하는 편이 쉽다.
- 잘 돌고 있는지 확인: 백업 폴더의 `backup.log` 마지막 줄에 "완료" 가 찍힌다. `deploy\backup-data.cmd` 를 두 번 눌러 직접 실행해도 된다.

### 서버가 죽었을 때 되살리기

1. 새 PC(또는 복구한 서버)에 **Node.js** 를 설치한다.
2. 백업의 `full` 폴더를 `C:\ims\monitor` 로 통째로 복사한다.
   - `full` 이 없으면: GitHub 에서 ZIP 을 받아 `C:\ims\monitor` 에 풀고, `daily\최신날짜` 폴더의 파일을 `monitor\data` 안에 넣는다.
3. `monitor\deploy\setup-collector.cmd` 를 더블클릭한다.
4. 브라우저에서 `http://<서버IP>:15138/` 을 연다. 계정·일정·설정·이력이 그대로 살아 있다.

**IP 를 같게(192.168.0.9) 복구하면 각 서버의 에이전트는 손댈 필요가 없다.** 5초마다 다시 붙는다.
IP 가 달라지면 각 서버에서 `C:\ProgramData\IMSMonitoringAgent\agent.conf` 의 `URL=http://새주소:15138/api/metrics` 를 고치고 에이전트를 다시 시작하거나(작업 스케줄러 `IMSMonitoringAgent`), 새 주소로 설치 파일을 다시 실행한다.

### 얼마나 자주, 무엇을 확인하나

- 하루 한 번 자동. 용량은 작다(보통 수 MB ~ 수십 MB).
- 한 달에 한 번, 백업 폴더에 어제 날짜 폴더가 있는지만 보면 된다.
- 계정 비밀번호를 모두 잊었을 때는 복구가 아니라 `data\users.json` 을 지우고 수집기를 다시 시작하면 admin 으로 초기화된다.
